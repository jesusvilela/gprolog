## Corrections, scope qualifications, and retirements

No scientific correction, missing source, instrument failure, source replacement, bug-driven reference oracle rewrite, workload resampling or tuning occurred in the first complete run. The raw record, complete corpus and primary metric are retained unchanged.

**Scope qualification:** A Prolog process returning exit status 0 may still report `ERROR:` from source-loading directives. The initial protocol already anticipated this; the observed three Scryer cases confirm why a source-loaded-versus-error typed representation is required.

**Retired interpretations:** (1) project-curated seven-source acceptance can be reported as a general Prolog conformance rate; (2) the Scryer source files in an SWI 9.0.4 environment constitute clean semantic reference programmes; (3) accepting a slash token in a module export list, by itself, would be sufficient evidence of whole-file module compatibility.

**Independence remainder:** The reference interpreter is independently implemented but the programme selection, tests and review were authored within the same project; the SWI reference and SWI test files share organisational origin. For Scryer sources SWI has greater code-origin independence but those three source loads are not clean in the chosen version.

**Resource remainder:** No source timing, memory, CPU-cycle or real-world performance measurements were collected or promoted. No Gen19 ownership policy change was made.
